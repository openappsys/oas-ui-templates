# desktop —— 桌面体验模板（立项章程）

> 状态：**已立项（2026-10-06），v0 骨架同日落地**
> 定位：模板仓第 8 个交付形态——**浏览器内的桌面软件体验**（窗口系统 + 任务栏 +
> 应用窗口），不是原生桌面应用（Tauri/Electron 方向已否决：不需要原生打包，
> 只要桌面软件的观感与交互）。

## 1. 背景与定位

oas-ui 是标准 web components，桌面体验即「用窗口管理器组织后台能力」：
壁纸 + 桌面图标 + 可拖动/最小化/最大化的应用窗口 + 任务栏。与 admin-pro
（文档流后台）、mobile-h5（移动 App）并列的第三种产品形态。
（2026-10-06 原方向 Tauri 原生壳经用户定夺否决——**只要效果，不要原生**，
本章程为改向后重写。）

## 2. 交互范式

- 壁纸 + 桌面图标：单击/双击打开应用窗口
- 窗口管理：标题栏拖动移动、最小化（收进任务栏）、最大化（铺满桌面）、
  关闭；点击置顶（焦点层级）
- 任务栏：启动器（应用列表）+ 运行中窗口按钮 + 右侧时钟
- 应用 = 后台能力的窗口化：仪表盘 / 订单 / 用户 / 设置（外观与皮肤）

## 3. 技术口径

- 零框架 + web components（对齐 mobile-h5）：`@oas-ui/ui` 按需注册 +
  `@oas-ui/theme`（index/skins/glass）+ icons
- 窗口管理器为模板自研（约 200 行：pointer 拖动 + z-index 焦点栈 + 状态机），
  窗口内控件全部消费 oas-* 组件
- oas-modal 自带 draggable 能力是单弹窗级；多窗口管理器属模板职责

## 4. 范围

### v0（同日落地）
- 桌面/任务栏/窗口三件套 + 四个应用窗口（仪表盘/订单/用户/设置）
- 设置应用内接皮肤切换 + 玻璃质感（与全家族同键名契约）

### v1（候选项，未排期）
- 窗口缩放（边缘拖拽）、多实例、窗口吸附、开始菜单二级
- 深浅色跟随系统、窗口位置持久化

### 明确不做
- 原生打包（Tauri/Electron）、离线数据层、真实多用户

## 5. 验收

- e2e：开窗/聚焦/最小化/最大化/关闭 + 任务栏时钟存在
- 窗口拖动后位置保持；最小化后任务栏按钮可还原
- `pnpm --filter desktop build` + e2e 全绿
